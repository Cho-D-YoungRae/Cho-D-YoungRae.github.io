# Feature Specification: 심플스택 기술 블로그

**Feature Branch**: `001-tech-blog`
**Created**: 2026-02-14
**Status**: Draft
**Input**: User description: "깃허브 개발자 기술 블로그. 단일 작성자(Cho-D-YoungRae). 블로그명 '심플스택'. 게시글 작성/발행/초안/숨김, 태그, 아카이브, 검색, RSS/Atom, 사이트맵, SEO 메타데이터, 가독성 기능 제공."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 게시글 작성 및 발행 (Priority: P1)

블로그 작성자(Cho-D-YoungRae)가 Markdown 형식으로 기술 게시글을 작성하고, 완성된 글을 블로그에 발행하여 모든 방문자가 읽을 수 있도록 한다. 게시글에는 제목, 본문, 작성일, 태그, 요약 설명을 포함한다.

**Why this priority**: 블로그의 핵심 가치는 글을 작성하고 공유하는 것이다. 이 기능 없이는 블로그가 존재할 이유가 없다.

**Independent Test**: 하나의 게시글을 작성하고 발행한 뒤, 블로그 메인 페이지에서 해당 글이 목록에 노출되고 클릭하면 전체 내용을 읽을 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자가 Markdown 파일에 제목, 본문, 작성일, 태그를 포함한 게시글을 작성했을 때, **When** 해당 글을 발행 상태로 설정하면, **Then** 블로그 메인 페이지의 게시글 목록에 해당 글이 최신순으로 노출된다.
2. **Given** 방문자가 블로그 메인 페이지에 접속했을 때, **When** 게시글 목록에서 특정 글을 클릭하면, **Then** 해당 글의 전체 본문, 작성일, 태그가 표시된다.
3. **Given** 발행된 게시글이 존재할 때, **When** 게시글 목록 페이지를 확인하면, **Then** 각 게시글이 제목, 작성일, 요약 설명, 태그와 함께 목록 형태로 표시된다.

---

### User Story 2 - 게시글 상태 관리: 초안 및 숨김 (Priority: P2)

작성자가 아직 완성되지 않은 글을 초안(비발행) 상태로 관리하고, 특정 글을 숨김 처리하여 직접 링크를 가진 사람만 접근할 수 있도록 한다.

**Why this priority**: 작성자가 글을 작성하는 과정에서 미완성 글이 공개되지 않도록 보호하고, 특정 대상에게만 공유하고 싶은 글을 관리하는 데 필수적이다.

**Independent Test**: 초안 글이 블로그 목록에 노출되지 않음을 확인하고, 숨김 글이 목록에는 없지만 직접 URL로 접근하면 읽을 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자가 게시글을 초안 상태로 설정했을 때, **When** 방문자가 블로그 메인 페이지를 확인하면, **Then** 해당 초안 글은 게시글 목록, 태그 페이지, 아카이브, 검색 결과, RSS 피드 어디에도 노출되지 않는다.
2. **Given** 작성자가 게시글을 숨김 상태로 설정했을 때, **When** 방문자가 블로그 메인 페이지나 태그 페이지, 아카이브, 검색 결과를 확인하면, **Then** 해당 숨김 글은 목록에 노출되지 않는다.
3. **Given** 숨김 상태의 게시글이 존재할 때, **When** 해당 글의 직접 URL을 알고 있는 사용자가 URL로 접근하면, **Then** 해당 글의 전체 내용이 정상적으로 표시된다.
4. **Given** 작성자가 초안 글의 작성을 완료했을 때, **When** 해당 글을 발행 상태로 변경하면, **Then** 블로그 목록, 태그 페이지, 아카이브에 즉시 노출된다.

### User Story 3 - 가독성: 목차, 헤딩 앵커, 코드 하이라이트 (Priority: P3)

방문자가 기술 게시글을 편리하게 읽을 수 있도록, 긴 글에서 목차(Table of Contents)를 통해 원하는 섹션으로 이동하고, 코드 블록이 문법 강조(syntax highlighting)되어 표시된다.

**Why this priority**: 개발자 기술 블로그에서 코드 가독성과 긴 글의 탐색 편의성은 독자 경험의 핵심이다. 블로그 콘텐츠의 품질을 결정하는 요소이다.

**Independent Test**: 코드 블록이 포함된 긴 게시글을 작성하고, 목차가 자동 생성되는지, 헤딩 클릭으로 해당 섹션으로 이동하는지, 코드가 문법 강조되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 2개 이상의 헤딩(h2, h3 등)이 포함된 게시글이 발행되었을 때, **When** 방문자가 해당 글을 열면, **Then** 본문 내 헤딩들을 기반으로 목차(TOC)가 자동 생성되어 표시된다.
2. **Given** 목차가 표시된 게시글에서, **When** 방문자가 목차의 특정 항목을 클릭하면, **Then** 해당 헤딩 위치로 부드럽게 스크롤 이동한다.
3. **Given** 게시글 내 헤딩 요소가 존재할 때, **When** 방문자가 해당 헤딩에 마우스를 올리거나 클릭하면, **Then** 해당 헤딩의 앵커 링크가 표시되어 URL로 직접 공유할 수 있다.
4. **Given** 프로그래밍 언어가 지정된 코드 블록이 포함된 게시글이 발행되었을 때, **When** 방문자가 해당 글을 열면, **Then** 코드 블록이 해당 언어의 문법에 맞게 색상 강조되어 표시된다.

---

### User Story 4 - 태그 기반 탐색 (Priority: P4)

방문자가 관심 있는 기술 주제의 태그를 통해 관련 게시글을 모아 볼 수 있다. 작성자는 게시글에 하나 이상의 태그를 부여하고, 방문자는 태그 목록 페이지와 개별 태그 페이지를 통해 글을 탐색한다.

**Why this priority**: 기술 블로그에서 주제별 분류는 독자가 관심 분야의 글을 효율적으로 찾는 핵심 탐색 수단이다.

**Independent Test**: 여러 태그가 부여된 게시글들을 작성하고, 태그 목록 페이지에서 태그를 클릭하면 해당 태그의 게시글만 필터링되어 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 태그가 부여된 게시글들이 존재할 때, **When** 방문자가 태그 목록 페이지에 접근하면, **Then** 사용된 모든 태그가 목록 형태로 표시된다.
2. **Given** 특정 태그가 부여된 게시글이 3개 존재할 때, **When** 방문자가 해당 태그를 클릭하면, **Then** 해당 태그가 부여된 3개의 게시글만 목록으로 표시된다.
3. **Given** 게시글 상세 페이지에서, **When** 게시글에 부여된 태그가 표시될 때, **Then** 각 태그를 클릭하면 해당 태그의 게시글 목록 페이지로 이동한다.

---

### User Story 5 - 아카이브: 작성일 기반 탐색 (Priority: P5)

방문자가 게시글을 작성일 기준으로 탐색할 수 있는 아카이브 페이지를 제공한다. 연도/월별로 게시글을 그룹화하여 시간순 탐색이 가능하다.

**Why this priority**: 작성일 기반 탐색은 블로그의 역사적 맥락을 파악하고 과거 글을 찾는 보조적 탐색 수단이다.

**Independent Test**: 여러 날짜에 작성된 게시글이 존재할 때, 아카이브 페이지에서 연도/월별로 그룹화되어 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 여러 날짜에 작성된 게시글들이 존재할 때, **When** 방문자가 아카이브 페이지에 접근하면, **Then** 게시글이 연도별로 그룹화되어 최신순으로 표시된다.
2. **Given** 아카이브 페이지에서, **When** 방문자가 특정 게시글 제목을 클릭하면, **Then** 해당 게시글 상세 페이지로 이동한다.

---

### User Story 6 - 게시글 검색 (Priority: P6)

방문자가 키워드를 입력하여 블로그 내 게시글을 검색하고 관련 결과를 빠르게 찾을 수 있다.

**Why this priority**: 검색은 태그나 아카이브로 찾기 어려운 특정 내용을 직접 찾는 수단이지만, 태그와 아카이브가 기본 탐색을 충분히 지원하므로 우선순위가 상대적으로 낮다.

**Independent Test**: 검색창에 키워드를 입력하고, 해당 키워드가 포함된 게시글이 검색 결과에 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 방문자가 블로그에 접속했을 때, **When** 검색 기능을 활성화하면, **Then** 키워드를 입력할 수 있는 검색 인터페이스가 표시된다.
2. **Given** "React"라는 단어가 포함된 게시글이 2개 존재할 때, **When** 방문자가 "React"로 검색하면, **Then** 해당 2개의 게시글이 검색 결과에 표시된다.
3. **Given** 방문자가 존재하지 않는 키워드로 검색했을 때, **When** 검색 결과가 없으면, **Then** 결과가 없다는 안내 메시지가 표시된다.

---

### User Story 7 - SEO, 메타데이터, 사이트맵, RSS/Atom 피드 (Priority: P7)

블로그와 각 게시글이 검색 엔진에 최적화되고, 소셜 미디어 공유 시 적절한 미리보기가 표시되며, 구독자가 RSS/Atom 피드로 새 글을 받아볼 수 있다.

**Why this priority**: SEO와 피드는 블로그의 발견 가능성과 구독 편의를 높이는 중요한 기능이지만, 핵심 콘텐츠 작성/탐색 기능 이후에 구현해도 무방하다.

**Independent Test**: 게시글의 HTML 소스에서 OG/Twitter 메타태그 존재를 확인하고, 사이트맵 URL 접근과 RSS/Atom 피드 URL 접근이 가능한지 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행된 게시글이 존재할 때, **When** 해당 페이지의 HTML 소스를 확인하면, **Then** Open Graph(og:title, og:description, og:image, og:url)와 Twitter Card(twitter:card, twitter:title, twitter:description) 메타태그가 포함되어 있다.
2. **Given** 블로그에 발행된 게시글들이 존재할 때, **When** 사이트맵 URL에 접근하면, **Then** 모든 발행된 게시글의 URL이 포함된 유효한 사이트맵이 반환된다.
3. **Given** 블로그에 발행된 게시글들이 존재할 때, **When** RSS 피드 URL에 접근하면, **Then** 발행된 게시글들이 포함된 유효한 RSS 2.0 형식의 피드가 반환된다.
4. **Given** 블로그에 발행된 게시글들이 존재할 때, **When** Atom 피드 URL에 접근하면, **Then** 발행된 게시글들이 포함된 유효한 Atom 형식의 피드가 반환된다.
5. **Given** 블로그 메인 페이지와 각 게시글 페이지에서, **When** HTML 소스를 확인하면, **Then** 적절한 title 태그, meta description, canonical URL이 설정되어 있다.

---

### Edge Cases

- 태그가 하나도 없는 게시글이 발행되었을 때, 게시글 목록과 상세 페이지에서 태그 영역이 어떻게 표시되는가?
- 동일한 날짜에 여러 게시글이 작성되었을 때, 아카이브에서 정렬 순서는 어떻게 되는가?
- 게시글 본문에 헤딩이 하나도 없을 때, 목차(TOC)는 표시되지 않아야 한다.
- 매우 긴 게시글(10,000자 이상)에서 목차와 코드 하이라이트가 정상 동작하는가?
- 검색어에 특수문자가 포함되었을 때, 검색이 정상 동작하는가?
- 숨김 게시글의 URL이 사이트맵, RSS 피드에 포함되지 않아야 한다.
- 초안 게시글이 검색 인덱스에 포함되지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 Markdown 형식으로 게시글 작성을 지원해야 한다 (MUST). 각 게시글에는 제목, 본문, 작성일, 요약 설명을 포함한다.
- **FR-002**: 시스템은 게시글에 발행(published), 초안(draft), 숨김(unlisted) 세 가지 상태를 지원해야 한다 (MUST).
- **FR-003**: 초안 상태의 게시글은 블로그의 어떤 공개 페이지(목록, 태그, 아카이브, 검색, 피드)에도 노출되지 않아야 한다 (MUST).
- **FR-004**: 숨김 상태의 게시글은 공개 목록(메인, 태그, 아카이브, 검색, 피드, 사이트맵)에 노출되지 않되, 직접 URL로는 접근 가능해야 한다 (MUST).
- **FR-005**: 시스템은 게시글에 하나 이상의 태그를 부여할 수 있어야 한다 (MUST). 태그는 선택 사항이다.
- **FR-006**: 시스템은 모든 태그를 보여주는 태그 목록 페이지를 제공해야 한다 (MUST).
- **FR-007**: 시스템은 특정 태그가 부여된 게시글만 모아 보여주는 태그별 게시글 목록 페이지를 제공해야 한다 (MUST).
- **FR-008**: 시스템은 게시글을 작성일 기준으로 연도별 그룹화하여 보여주는 아카이브 페이지를 제공해야 한다 (MUST).
- **FR-009**: 시스템은 게시글 제목과 본문 내용을 대상으로 키워드 검색 기능을 제공해야 한다 (MUST).
- **FR-010**: 시스템은 2개 이상의 헤딩이 포함된 게시글에 대해 자동으로 목차(TOC)를 생성해야 한다 (MUST).
- **FR-011**: 시스템은 게시글 내 각 헤딩에 앵커 링크를 제공하여 URL로 특정 섹션을 공유할 수 있어야 한다 (MUST).
- **FR-012**: 시스템은 프로그래밍 언어가 지정된 코드 블록에 대해 문법 강조(syntax highlighting)를 적용해야 한다 (MUST).
- **FR-013**: 시스템은 유효한 RSS 2.0 형식의 피드를 제공해야 한다 (MUST).
- **FR-014**: 시스템은 유효한 Atom 형식의 피드를 제공해야 한다 (MUST).
- **FR-015**: 시스템은 모든 발행 게시글의 URL이 포함된 사이트맵을 자동 생성해야 한다 (MUST).
- **FR-016**: 시스템은 각 페이지에 Open Graph 및 Twitter Card 메타태그를 포함해야 한다 (MUST). OG 이미지는 블로그 기본 이미지 1장을 모든 페이지에 공통으로 사용한다.
- **FR-017**: 시스템은 '심플스택'을 블로그 명칭으로 표시해야 한다 (MUST). 게시글에 별도 작성자 정보는 표시하지 않는다.
- **FR-018**: 시스템은 다크 모드와 라이트 모드를 지원하며, 사용자의 시스템 설정을 존중해야 한다 (MUST).
- **FR-019**: 게시글 목록은 작성일 기준 최신순으로 정렬되어야 한다 (MUST).
