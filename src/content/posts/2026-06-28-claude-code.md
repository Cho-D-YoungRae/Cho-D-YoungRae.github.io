처음 클로드 코드를 사용했을 때부터 지금까지의 활용에 대한 히스토리 그리고 앞으로 해보고 싶은 것을 정리하려고 한다.

잘 사용하고 있는 것들도 있지만, 인터넷에서는 꽤 좋다고 했던 것들이 실제 사용했을 때는 그렇게 내게 맞지 않는 것들도 있었다.

> 내가 제대로 활용하지 못하고 있을지도...

클로드나 챗지피티는 이전부터 계속 활용은 하고 있었으나 클로드 코드를 집중적으로 사용하게 된 것은 2025년 8월 중순쯤 부터였다. 그때부터 거의 손으로 코드를 직접 작성하는 것은 하루에 10줄 이하였던 것 같고 요즘은 진짜 거의 직접 작성하지 않는다.

클로드 MAX 200 구독을 사용하고 있다.

## 이전 활용 법

클로드를 처음 사용했을 때부터 약 2026년 3월까지의 내용이다.

### SuperClaude

> [github](https://github.com/SuperClaude-Org/SuperClaude_Framework)

SuperClaude 를 사용했다.

CLAUDE.md 에 프롬프트를 추가해주어서 Claude 를 더 똑똑하게 해주고, 작업할 때 필요한 커맨드(`implement`, `brainstroming`, ...), MCP, Agent를 제공해주는 프레임워크다.

이전에는 추가해주는 것이 좋다고 생각했으나 opus 4.6 출시 이후로 기본적인 모델 역량이 증가해서 그런지 불필요할 것 같다는 생각이 들었고 빼서도 써보고 하다가 opus 4.7 출시 이후로 완전히 **제거했다**.

SuperClaude 를 설치하면 넣어주는 MCP 중 이후에도 사용해야되는 것들(serena, context7, 등)은 플러그인을 통해서 설치해서 사용하고 있다.

### 플랜 모드

클로드 코드를 처음 사용했을 때 가장 유용한 기능이라고 생각했다.

그냥 작업을 시키면 생각처럼 결과가 안나오는 경우가 많았고 작업을 시킨 뒤 수정하는 것보다 계획을 먼저 만들고 계획을 수정한 뒤 실행하는 것이 더 만족스러웠다.

현재까지 **계속 사용하고 있다**.

### Spec-kit

[github](https://github.com/github/spec-kit)

클로드 코드를 사용할 때 스펙을 명확히 해주는 것이 중요하다며 SDD(Spec-Driven-Development) 관련 키워드가 많이 거론되던 시기가 있었고 그때 당시 여러가지 도구들이 나왔는데 그 중 스펙킷을 집중해서 사용했었다.

명세를 작성해나가며 구체화해가고 이를 통해서 작업 계획을 잡은 뒤 실행하는 형태였다.

플랜보다 더 큰 작업 혹은 바이브 코딩을 할 때 사용하곤 했다.

최근에는 superpowers 를 사용하면서 **사용하지 않게 되었다**.

## 최근 활용

### auto mode

이전에는 플랜 모드를 승인하거나 편집 권한 요청을 하지 않고 작업시키려면 `accept edits on` 모드를 사용했었다.

`dangerously-skip-permissions` 모드 관련해서도 들었으나 위험해보여서 시도하지 않았다.

`auto` 모드는 도구를 실행하기 전에 모델이 요청을 사전 평가한다.

최근에는 플랜 승인이나 작은 작업이어서 별도 확인이 필요하지 않을 경우 오토 모드를 사용한다.

### superpowers

> [github](https://github.com/obra/superpowers)

'기획서 작성 → 구현 계획 수립 → 코드 작성 → 별도 리뷰어 에이전트' 의 프로세스를 통해 작업한다.

Spec-kit을 사용했을 때는 작업 결과가 실행되지 않거나 오류가 발생하는 경우도 많았는데 superpowers 를 사용했을 때는 거의 그런 기억이 없다.

기획을 하면서 모호한 부분을 구체화하고 작업계획을 세운다. subagent 를 통해서 작업을 하고 리뷰어를 통해서 리뷰하며 개발과 테스트를 함께한다.

요즘 큰 작업은 거의 superpowers 를 사용한다.

대신에 오래걸리는 단점이 있다.

작업의 크기에 따라: 오토 모드 -> 플랜 -> superpowers

### 클로드 코드 데스크탑

클로드 데스크탑의 클로드 코드 UI 가 개선되면서 클로드 데스크탑으로 많이 작성한다.

인텔리제이, vscode 에서 클로드 코드를 사용했을 때보다 코드 참조에서는 좀 더 불편함이 있다.

하지만 병렬작업에서 굉장히 편함을 느끼고 있다.

이전에 병렬 작업을 위한 터미널 도구들 혹은 [conductor](https://www.conductor.build/)와 같은 것들을 사용해봤는데 다들 조금씩 불편함이 있었다.

클로드 데스크탑의 클로드 코드를 사용했을 때 현시점에서 병렬 작업이 가장 편했다(git worktree 도 딸깍)

### CLAUDE.md 컨텍스트

이전에는 CLAUDE.md 컨텍스트에 개발 관련 지침 위주로 추가했었다.

하지만 요즘에는 좀 더 클로드 코드의 작업 흐름에 나의 개입을 줄이고 싶다는 생각을 한다.

루트 CLAUDE.md 에는 개발 환경이나 사용 가능한 도구들을 넣어주고 있다.

```markdown title="CLAUDE.md"
## Development Environment

### Java

- Java 21 (default), Java 25 available via sdkman
- SDK manager: sdkman (`sdk use java <version>`)

### Python

- Python 3.12 (default version)
- Package manager: uv

### Node.js

- Node 24 (default version)
- Version manager: fnm (`fnm use <version>`)
- Package manager: pnpm

### CLI Tools

- GitHub CLI: `gh`
- PostgreSQL CLI: `psql`
- MySQL CLI: `mysql`
- AWS CLI: `aws`
```

프로젝트의 CLAUDE.local.md 에는 DB 읽기 전용 계정을 추가해서 디버깅 등에 활용하려고 하고 있다.

올해부터 컨텍스트 크기가 1M 으로 증가됨에 따라 컨텍스트에 좀 더 다양한 정보를 넣어줘보려고 생각하고 있다.

도메인 관련 정보, 도메인 아키텍처, 소프트웨어 아키텍처을 추가해서 클로드 코드의 판단력을 올려주고 작업 흐름에 나의 개입을 더 줄여나가볼 생각이다.

## 그 외 끄적끄적

Codex

- 작업에 따라 클로드보다 나을 때도 있고(opus 4.7, GPT-5.5 기준)
- superpowers 도 있어서 쓰기 좋았음
- 하지만 아직 클로드 코드의 플러그인이나 사례 등 생태계가 더 풍부해서 클로드 코드만 사용하기로 함

[Claude Code Codex plugin](https://github.com/openai/codex-plugin-cc)

- 클로드 코드 작업 후 코덱스로 리뷰하여 작업을 보완해주기도 하였으나
- 오히려 코덱스 리뷰로 인해서 클로드 코드의 작업은 정상이었는데 혼란을 주기도 함
- 그리고 너무 느려짐

[codegraph](https://github.com/colbymchenry/codegraph)

- 붙여서 써보고는 있다
- 큰 차이는 잘 모르겠으나 떼면 역체감이 있으려나...

[Pencil](https://www.pencil.dev/)

- 로컬 디자인 도구
- 작업 결과가 원하는 대로 나오지 않아서 사용하지 않게됨(요즘은 좀 나아졌으려나)
- 이후에 유료가 될 수도 있다는 것도 있고

Claude Code remote control

- 종종 작업을 폰으로 세션 넘겨받아서 하고 있음
- 폰으로 작업하는 것을 계속 시도해볼 예정

Subagent, Team

- 서브 에이전트는 이전부터 계속 사용하고 있었음
  - 클로드 코드가 알아서 사용하기도 하고
- 팀은 아직 제대로 사용해보지 않음. 사용해봐야 겠다.

울트라 플랜

- 플랜모드로 하기에는 조금 커보이고 superpowers 사용할 정도는 아닌 것 같을 때 사용
- 아직은 약간 느낌적으로 분류해서 사용하는 정도

## 앞으로 더 해보려는 것

기획, 마케팅

- 이전에 바이브코딩 관련해서 보면 PRD 를 작성해라 뭐 이런 것들이 있었는데 이런 기획을 클로드 코드로 잘 하는 것을 시도해봐야 겠다
- [manyfast](https://manyfast.io/ko/) 한번 결제해봤는데 써봐야지
- 마케팅도 해볼 수 있으려나
- 신규 프로젝트나 서비스를 만들 때 약간 사업적으로 유효한지(?) 이런 것도 검증해보고 싶다

디자인

- 클로드 디자인 나오자마자 써봤는데 엄청 마음에 들지는 않았다. 요즘 뭔가 업데이트 되고있는 것 같은데 더 써봐야지
- [opendesign](https://github.com/nexu-io/open-design) 은 써보려고 하고 있음.

용어 사전

- 프로젝트를 하면 용어 사전을 관리하는 경우가 있는데 이를 클로드 코드 워크플로우 안에 녹여보고 싶다
- 또 클로드 코드도 용어 사전을 참조할 수 있다면 더 잘할 수 있을 것이라 생각된다

아키텍처

- 도메인 아키텍처든 소프트웨어 아키텍처든 CLAUDE.md 컨텍스트에 잘 녹여서 넣어주고 싶다.
- 그렇지 않으면 가끔 내가 원하지 않는 대로 결과가 나올 때가 있다. 특히 요즘은 작업을 작게 시키기 보다는 길게 시키려고 하고 있어서 이런 것이 더 필요함을 느낀다.
- 이런 것을 잘 구성해서 넣어주려면 결국 나의 개발 공부가 더 필요함을 느낀다.
